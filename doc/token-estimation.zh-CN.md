# Token 估算与工具结果图像

OAIProxy 会解码 UTF-8 文本 DataPart，并以图像形式发送受支持的工具结果图像。它绝不会把图像字节数组序列化成数字 JSON 工具文本。不受支持的二进制内容会变成简短的 MIME/大小占位符。未知对象采用有界序列化，并配合二进制占位符、循环检测和可见的截断标记。普通文本输出会完整保留。

Anthropic 在 `tool_result` 内接收图像块。Chat Completions、Responses（包括 Codex OAuth）、Gemini 和 Ollama 会先收到文本形式的工具响应，随后收到一条包含相关图像的用户消息。连续并行工具调用批次中的所有结果都排在这条伴随消息之前。ID 与图像顺序保持不变。纯文本模型在配置了 Vision Bridge（视觉桥接）时会使用它；否则图像会变成占位符。已配置但不可用或执行失败的桥接仍会报告错误。

## 计数与预算

文本使用现有的内置 `o200k_base` 分词器。对于使用不同分词器的模型，这只是估算。如果初始化或分词失败，回退方案会把 ASCII 字符按 1/4 token 计数，把非 ASCII Unicode 码点按 1 token 计数。工具名称、参数、结果、定义以及输出的推理内容都会被计入。用量、缓存控制和 Responses 状态元数据不计入提示文本。

最终守卫会读取经过转换和 Vision Bridge 处理后的已准备请求，计数语义内容与帧结构预留量，而不是 JSON 封装或 base64 字符。状态栏和诊断使用这份报告。对于 Responses 续接，即使只传输增量，守卫也会统计完整的逻辑历史；缓存 token 仍然占用上下文。外部管理的显式 `previous_response_id` 历史如果不包含在提供的消息中，就无法在本地重建。

VS Code 的 `provideTokenCount` 使用相同的内容规范化、分词器和图像配置档。它不会发起网络请求。尚未缓存的桥接图像会获得临时预留额度；一旦描述被缓存，就可以按该描述计数。目标请求发出前，实际桥接文本会再次计数。适配器的帧结构/分组方式以及不可用的服务器历史，意味着逐消息总计不一定正好等于已准备请求总计或服务器用量。正确的计数并不保证 Copilot 的压缩行为。

硬性守卫和现有对外公布的预算仍然启用。特别是，配置为 1,050,000 token 的上下文目前会在模型选择器中归一化为 1,000,000，扣除 128,000 输出预留后剩余 872,000 输入 token。此改动不会修改上下文限制，也不会验证私有 OAuth 端点的限制。

## 实时估算输出速度

在普通模型请求期间，状态栏会显示上下文百分比和估算的响应速度，例如 `23.4% · ~42.0 tok/s`。它每 500 ms 更新一次。悬停会附加一行紧凑信息，例如 `Speed ~42.0 tok/s · ~1.2K tok · 28.6s`。请求结束后会追加 `Done`、`Cancelled` 或 `Failed`；在产生输出之前，该行只显示 `Speed · Waiting…`。已取消和失败的请求会保留部分统计；最终估算值会一直显示到下一次普通请求。详细的计数说明保留在本指南中，以保持悬停信息简洁。

TPS 是估算的已接收输出 token 数除以从首个非空文本或思维内容开始经过的秒数。初始等待时间不计入，流式传输期间的停顿计入。流式传输结束时计时冻结，早于用量持久化。模型请求之间的工具执行不在测量范围内。产生输出前，显示为 `Waiting…`；空响应、仅含工具调用的响应，以及测量时间不足 500 ms 的响应会显示 `— tok/s`，而不是不稳定的速率。

该估算统计供应商暴露的回答文本和思维文本。隐藏推理、工具参数/结果以及用量或状态元数据不计入。思维摘要只测量收到的摘要文本，而非底层推理。供应商报告的输出总量不会替代该估算。这只是对流式速度的参考，不是计费用量，也不是对服务器端推理速度的测量。

计数使用内置的 `o200k_base` 分词器，并在分词器失败时使用相同的已配置字符回退方案，且不应用输入校准系数。文本与思维内容会分别按最大 4,096 个 UTF-16 代码单元的块计数，保留代理对，并只重新统计未完成的尾部。不同的模型分词器和块边界会带来近似误差。计数在块之间让出执行权，不会保留完整输出，也不会用输出文本填充输入 token 缓存。

最新的普通请求拥有显示权；较早的并发请求无法覆盖它的上下文或速度。连接诊断和内部 Vision Bridge 请求不会影响该显示。统计会自动启用，保存在内存中，并在扩展释放时清除。现有的上下文预算守卫、缓存详情、警告颜色和点击配置操作保持不变。

## 图像估算

PNG、JPEG、GIF 和 WebP 的尺寸直接从字节读取，无需解码像素。边界检查会遵循类型化数组的偏移量。无效或不支持的头部使用回退值。未知模型别名使用回退值，而不是仅根据 API 模式继承规则。支持的配置档如下：

| 配置档 | 规则 |
| --- | --- |
| `auto` | 识别出的 OpenAI 或 Claude 模型 ID 会选择有文档记录的配置档；其他 ID 使用 `unknown`。 |
| `openai-patches` | 32 像素补丁，按模型/细节等级调整尺寸并应用乘数。Astra auto/original 不使用高细节的 2,500 补丁上限。 |
| `openai-tiles` | 按文档调整尺寸后，使用模型特定的基础费用和 512 像素分块费用。 |
| `claude-standard` | 28 像素补丁，长边 1,568 像素，补丁预算 1,568。 |
| `claude-high` | 28 像素补丁，长边 2,576 像素，补丁预算 4,784。 |
| `unknown` | 可配置的固定回退值，初始为每张图像 8,192 token。 |

OpenAI 配置档依据[官方视觉指南](https://developers.openai.com/api/docs/guides/images-vision)；Claude 配置档依据[官方视觉指南](https://platform.claude.com/docs/en/build-with-claude/vision)，两者均于 2026 年 9 月 29 日复核。计数仍然是估算，在网关和 OAuth 路由上尤其如此。Gemini 以及本地/其他网关别名会使用显式回退值，直到有文档匹配的配置档或用户覆盖可用。原生视频输入保留现有的传输方式，并获得作为标注启发式规则的图像回退额度；这里不声称存在视频分词器。

对于一张 744×1053 的图像，Astra 配置档估算为 951 个图像 token；Claude 估算为 1,026 个。压缩或文件大小不会改变这些计数。估算器不会调整图像尺寸或重新压缩，也不保证上游接受该图像尺寸。未知/头部解析失败时使用的 8,192 回退值是一个未校准的预留额度，并不是所有模型或图像的通用上限。

## 设置

设置使用现有的 `oaicopilot` 命名空间。默认值如下：

```jsonc
"oaicopilot.tokenEstimation": {
  "charsPerToken": 4,
  "nonAsciiTokensPerChar": 1,
  "maxSerializedPartChars": 200000,
  "bridgeTokens": 8192,
  "calibration": "observe",
  "image": {
    "strategy": "auto",
    "profile": "auto",
    "fixedTokens": 8192,
    "fallbackTokens": 8192,
    "areaDivisor": 750,
    "maxLongEdge": 2576,
    "maxTokensPerImage": 8192
  },
  "perModel": {}
},
"oaicopilot.debug.tokenBreakdown": false
```

`strategy: "fixed"` 使用 `fixedTokens`。`strategy: "area"` 是显式的自定义启发式规则：先缩放到 `maxLongEdge`，再用像素面积除以 `areaDivisor`，并以 `maxTokensPerImage` 为上限。这些面积默认值不是任何供应商的自动规则。`fallbackTokens` 处理无法读取的头部和未知模型。配置档覆盖对网关别名很有用；请选择与实际底层模型匹配的配置档。对于无法识别的名称，OpenAI 配置档覆盖会分别使用通用的 1.2× 补丁/高细节限制，或 85+170 分块公式。

覆盖值按以下顺序合并：默认值、全局字段、基础模型 ID、完整 `modelId::configId`。图像子字段会在每一步合并。例如：

```jsonc
"oaicopilot.tokenEstimation": {
  "perModel": {
    "local-vision::ollama": {
      "image": { "strategy": "fixed", "fixedTokens": 4096 }
    }
  }
}
```

无效值会回退到默认值。没有旧版开关可以恢复二进制序列化。修改估算设置会影响后续请求，无需安装另一个扩展构建。

## 诊断与校准

同时启用 `oaicopilot.logLevel: "debug"` 和 `oaicopilot.debug.tokenBreakdown: true`。OAIProxy 的输出/文件日志会包含：

- `request.tokenBreakdown`：关联的请求 ID、逻辑/传输估算值、分类、部分类型总计、最大的五个部分，以及图像配置档/置信度。
- `request.tokenComparison`：估算值、报告的输入用量、实际值/估算值比率、用量可用性以及校准资格。
- `request.contextTooLarge`：预算和最大的部分。面向用户的错误也会指出这些部分。

这些事件只包含类型、ID 和大小，绝不包含消息文本或 base64。图像贡献者会保留来源消息/部分/调用信息；其他已准备内容的贡献者会标明其转换后的消息/部分位置。缺失的流式用量会标记为未报告，绝不会当作零。现有的适配器用量规范化涵盖缓存输入，包括 Anthropic 的缓存创建/读取 token。

`calibration: "observe"` 会记录数值 EWMA 状态，但不改变估算值。`"adaptive"` 会在 20 个符合条件的、已完成的、无状态的纯文本请求之后应用乘数。EWMA α=0.1，范围限制在 [1,2]，绝不会降低估算值。图像/视频、Vision Bridge、诊断、已取消、未报告用量和有状态请求不参与校准。实际用量会与未校准的估算值比较，以避免反馈放大。缓存输入不会被扣除。记录按端点、API 模式、完整模型/配置 ID 以及估算设置/修订版本隔离；只持久化摘要和数值状态，最多 100 个配置。

## 面板与聊天计时

启用 `oaicopilot.logLevel: "debug"` 后，无需开启 token 明细即可获得计时事件：

- `config.open`、`config.htmlReady`、`config.ready`、`config.credentialsReady` 和 `config.initialized` 共享同一个面板 ID。它们区分 HTML 加载、webview 就绪握手和凭据加载。面板在设置就绪前会显示加载状态；凭据失败时提供 Retry。
- `request.timing` 与 `request.start`、`request.end` 及请求错误共享请求 ID。其阶段涵盖供应商入口、可选的 Vision Bridge、预检与估算、分发、响应头、流处理、首批接收字节、首个文本/思维/工具调用、用量持久化和完成。分发/响应头事件包含重试的尝试次数。请使用 `dispatch` 而不是更早的 `request.body` 摘要来测量等待响应头的时间。
- `tokenCount.summary` 在计数期间每秒聚合一次各模型的回调（并在释放时刷新）。它会报告调用次数、字符串调用次数、总字符数/消息部分数、token 总和、回调耗时总和/最大值、取消和失败。耗时总和包含任何调度等待，并发回调之间可能重叠；它不是 CPU 测量值。计数可能发生在供应商请求之外。由于提示构建可能触发数万次回调，逐回调的起止日志已被移除。

这些计时事件不包含提示、响应文本、凭据或请求 URL。`firstChunk` 可能是 keepalive；`firstText` 表示文本已交付给 VS Code，并不证明 UI 已绘制。时长包含调度等待，`complete` 标记供应商调用结束，即使调用失败或被取消。请结合 Copilot/扩展宿主日志，排查进入供应商之前或完成之后的延迟。

计数会复用已解析模型/设置上下文的有界缓存，并在 OAIProxy 配置变更、供应商刷新和校准更新时失效。现有的有界分词器缓存仍会处理重复字符串。在最多 128 次回调启动或 8ms 时间片之后，计数高峰会让出扩展宿主事件循环，使排队的命令、取消操作和 webview 工作得以运行。单次分词器操作可能超过该时间片；这不是严格的延迟保证。二进制转换和图像计数始终启用。

## 验证限制

无头测试覆盖了不同字节大小的有效 PNG、全部五个适配器、并行工具排序、解码/未知二进制、图像头部、分词器失败、配置、Vision Bridge、校准以及本地 localhost HTTP 重放。实时 Copilot/OAuth 重放需要用户安装测试扩展。请在那里验证真实的图像理解和流式用量；不要把本地转换测试当作上游模型确实看到了图像的证据。在评估校准准确性之前，请至少收集 20 个真实且符合条件的请求。无需新增依赖。
